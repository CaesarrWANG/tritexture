旧模型探索：采样点、监督点与大面切分

问题：注意力 latent 的旧模型，是不是被每面 28 个采样点、每步只监督 8 个点限制住了？做法：在 ≤ 8192 面子集上以同一配方各训 10k 步，分别加大输入采样点、监督点，以及把大面递归切小；再把练到 200k 的模型放到切分后的 mesh 上推理。

结论：在 10k 步内，加采样点、加监督点都没有让旧模型越过 const；大面切分带来的提升与 const 自身的位移相当。练够的 200k + 退火模型在小 mesh 上离 28 点插值上界只差 1 dB，推理时切分能再拿到超出 const 位移的真实增益。10k 步的实验只能说明早期学习不受点数限制，练够之后点数是否成为上限，需要在 200k 权重上微调 91 点输入才能回答。

4. 结论

  • 监督密度不是瓶颈。每步监督点从随机 8 个改成全部 91 个，10k 步只高 0.4 dB。
  • 输入采样密度在 10k 步内不是瓶颈。28 → 91 → 105 点，上界从 27 抬到 36 以上，模型反而略降。
  • 大面切分对 10k 模型只是任务变容易：重训后相对 const 只好 0.7 dB，仍在 const 以下。对练够的 200k + 退火模型，小 mesh 上是超过 const 位移的真实增益（+2.76），完整数据上则不足 const 位移（+0.64）。
  • 10k 步不足以下结论。网络先学低频再学高频，这个阶段看不出采样率对高频纹理的作用；练够的 200k + 退火模型在小 mesh 上离 28 点上界只差 1 dB，到那时点数才可能成为上限。

5. 后续计划的四点与进展（2026-10-21）

5.1 切分改为在线进行？

可以，已实现并验证。切分本身很便宜，关键是子面在新位置的采样点要重新从贴图上采。当初建缓存每个 mesh 要 1–2 秒，但分解后发现贵的不是贴图：

72,9130.05 s0.006 s0.31 s4.99 s

8 个随机训练 mesh，冷读，CPU。慢的是几何量（焊接、切割、谱分解），它们与切分无关、已经在缓存里；读 GLB 和为切分面采样只要零点几秒。

于是在线切分在数据进程里完成：几何和谱特征取自现有缓存，读 GLB 和贴图，递归切大面，只为切出来的子面从贴图上采 91 个点，新顶点的谱特征取两端点平均，锚点查询自动重映射到子面。每个 mesh 平均 0.27 秒，每张卡 4 个数据进程，远高于训练每步 2–3 秒的需求。阈值是运行时参数，不需要任何预处理，不占额外磁盘。

5.3 各进程的负载均衡

训练器一直开着按面数分桶（--size_bucket 1）：每一步各进程拿到面数相近的 mesh。面数预算模式可以在 5.1 的在线切分上实现：按 mesh 的总面积和预算决定每个面切几级，让每张卡的工作量和每单位面积的采样密度都一致。按 5.2 的测量，IO 只在 2 万面以上才显著，这个机制的收益有限，等实验需要再启用。
