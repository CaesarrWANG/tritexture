一句话结论：模型会画纹理，而且在有纹理的面上比"每面涂平均色"更好；它输在记不准大量纯色面的精确颜色。Objaverse 有 55% 的表面积是严格常数颜色的面，基线在那里几乎零误差，模型每面偏 2 到 10 / 255 就把总分拉到基线以下。

Round Q（第 6 节）：逐面 IO 的加权平均是第一道瓶颈，换成无损格点 IO 后旁路模型达到 interp 上限；接回 latent 后收益消失，损失随每个 latent 要代表的面数增长。固定数量的 latent 集合是当前瓶颈，oracle 实验进行中。

2. 数据：从 80 万到 12 万

三条基线的含义：const 把每个面涂成其 91 个采样点真值的平均色，是所有“每面一种颜色”方案里误差最小的；interp 只用编码器看到的 28 个输入点做线性插值，是一个只会重插值输入、不看上下文的模型的上限；z=0 把全部 latent 置零只靠几何解码，用来证明 latent 确实承载了纹理。

z=0 消融保持在 11 dB 左右，远低于模型本身，说明解码器确实依赖 latent，不存在"几何预测颜色"的捷径。KL 从 5.4 降到 0.68 nats/元素，高于鞋子 run 的 0.25，latent 承载的信息量更大。

直接读整体 PSNR 的结论是：10 万步后模型在三个指标上都低于每面平均色基线，而鞋子 run 在 area 上超过基线 0.5 dB、face 上持平。下面第 4 节解释为什么这个数字不能直接解读为"模型没学到东西"。

5. 交互式案例：GT · 重建 · const 同屏对比

10 个 held-out mesh（以 Objaverse 物体 ID 标识），每个嵌入一个 three.js 查看器。三个视图共用一个相机：拖拽旋转、滚轮缩放、右键平移，三边同步。左为原始贴图 (GT)，中为模型重建，右为每面平均色基线 (const)。贴图在 GT 的 UV 布局上烘焙成图集：每个材质一个图块（单材质 2048 × 2048，多材质 4096 × 4096 分块），无光照直接显示 albedo，模型默认缓慢自转，拖动时暂停、松手 3 秒后继续。每个案例下方并排给出 UV 空间的烘焙贴图（真值 / 重建），点击图片可打开原始分辨率。

const 是什么。它不是模型，是一把尺子：对每个三角面，取该面 91 个采样点真值颜色的平均值，把整个面涂成这一种颜色。每个面只剩 RGB 三个数，没有任何面内变化。

为什么取 91 个点的平均。91 个点是本项目里“一个面的纹理”的定义：每面放一个 12 阶重心坐标格点阵（91 点，向质心收缩 10% 避开接缝），cache 存的、损失算的、PSNR 评的都是这 91 个点。评估用均方误差，而使均方误差最小的常数恰好是算术平均，所以“91 点平均色”是所有每面常数方案里误差最小的，即最强的平面基线。

怎么看。右视图把每个面抹平，中间重建里比右视图多出来的细节，就是模型真正从 latent 解码出的面内纹理。Objaverse 有 55% 的表面积本来就是单色面，const 在那里是零误差的完美解，这也是整体 PSNR 低于它的原因（见第 4 节）。

6. Round Q：定位高频瓶颈（10 月 12 日至 14 日）

针对评审意见“真正的难点在面内纹理变化显著的面，尤其是大面”，用一组消融把损失定位到了具体环节。所有数字都在同一批 held-out mesh 上、以同一套脚本计算。

6.1 新参照：interp，只复述输入的上限

interp 把编码器看到的每面 28 个输入点线性插值到 91 个目标点，即“一个只会原样复述输入预算的方法”能达到的分数。模型低于它，说明输入里已有的信息在模型内部丢了；高于它，说明模型利用了面之外的上下文。

6.2 三个否定结果

  • latent 维度 64 → 256（容量 ×4）：零收益。5 万步时 23.02 / 24.09 / 27.55 对基线 22.83 / 23.91 / 27.38，20 个评估点平均差 −0.14 dB，训练损失和分面积表完全相同。
  • latent 数量 8192 → 4096（维度 256，总容量仍 ×2）：稳定低 0.9 dB。限制在 latent 的“个数”维度，不在宽度。
  • 再训 10 万步到 20 万步：主要涨在平坦面。常数面 +1.0 dB，有纹理面 +0.5 dB，其中面内变化（AC）只 +0.3 dB。20 万步加 1 万步退火得到目前最好的旧架构模型：25.89 / 27.04 / 31.12。

6.3 旁路消融：把 latent 集合整段拿掉

旁路模式下面 token 直接从编码器进解码器，每个面只看自己的 28 个点，测的是“逐面 IO 本身传不传信息”。原设计的 IO 是 attention pooling 编码器加逐点回归 MLP 解码器。替换方案是对固定格点阵无损的 IO：编码器把 28 个点按循环滚动后的格点顺序线性嵌入（等变、可逆），解码器一次输出 91 个格点颜色（任意点插值）。2 × 2 对照：

interp 上限格点 IO 旁路旧模型 200k+退火完整模型 + 格点 IO

一个被否定的解释：我们曾假设模型输出是“anchor 间距尺度上的低通场”。直接检验（模型输出与不同模糊半径的 GT 比较）显示三个模型都与 σ ≈ 0 到 1 纹素的 GT 最吻合，把 GT 模糊到 anchor 间距（约 6 纹素）反而更不像。误差的结构是“每面退化为近似常数”，不是空间低通。

6.5 高频细节的直接观察

在 UV 贴图上自动选取真值纹理最复杂的区域（384 像素裁剪，2048 贴图），从左到右：GT、旧模型 200k+退火、完整模型 + 格点 IO @25k、格点 IO 旁路。

6.6 当前的解释与正在做的检验

链路上有三处会丢高频：输入每面固定 28 个采样点（大面上信息在源头就缺失，interp 上限随面积从 30 降到 19 dB）；逐面 IO 的加权平均（已用格点 IO 消除）；固定 8192 个 latent 经两次跨面加权平均（当前瓶颈，损失随每 latent 面数增长，并且这条路径训练很慢）。几何 VAE 用同样结构可行，因为形状是低熵信号；纹理的信息量随贴图面积和频率增长，固定预算装不下。

正在进行的 oracle 实验：在面数 ≤ 8192 的 mesh 上让每个面独占一个放在质心的 latent，与“8192 个表面 FPS anchor”的控制组对比。若 oracle 接近旁路上限（这批 mesh 上 27.4 dB），则损失来自“多个面挤一个 latent”，方向是 latent 数量随 mesh 复杂度变化；若与控制组一样差，则 cross-attention 的读写机制本身需要重新设计。

7. 结论

  • 管线在 Objaverse 上成立。cotangent Laplacian 加 CGAL 切割的 cache 在 12 万个异构 mesh 上建成，谱分解失败率 1.3%；16 卡 DDP 稳定运行 26 小时，分桶采样使每步时间从预估的 2.3 秒降到 0.94 秒。
  • 模型在学纹理，并且比基线学得好。在真正有纹理的面上模型领先每面平均色基线 1.1 dB，且这一领先在所有 mesh 分组里都成立；z=0 消融证明 latent 被使用。
  • 整体 PSNR 低于基线是逐面颜色保真度问题，不是纹理问题。Objaverse 55% 的表面积是严格常数的面，模型在这些面上的平均颜色偏 2 到 10/255，视觉不可见但在 dB 上代价巨大。这也意味着在 Objaverse 上整体 PSNR 不是衡量这个模型的好指标。
  • 存在少数真正的泛化失败。罕见外观（全黑角色）被先验覆盖，提示编码器到解码器的颜色传递在细长稀疏结构上覆盖不足。
  • 逐面 IO 曾是第一道瓶颈，已修复。attention pooling 加逐点 MLP 在前 2.5 万步只学到每面平均色；无损格点 IO 让旁路模型 3 万步内达到 interp 上限（31.1 dB，比 const 高 5.4，比旧架构最好模型高 5.3）。
  • 固定数量的 latent 集合是当前瓶颈。加宽无效、减数变差、差距随每 latent 面数增长；格点 IO 的收益在接上 latent 后消失。穿过 latent 的信息路径训练慢，且在复杂 mesh 上容量不足。
  • 与原团队的对照需要谨慎。鞋子数据全部带贴图、面内方差大，const 基线弱得多；两组数字不能直接比较。

8. 下一步

  • 正在跑进行中：完整模型 + 格点 IO 的 5 万步版本（Slurm）；每面一个 latent 的 oracle 与控制组（本地）。
  • 评估口径：把"有纹理面上相对 const 的差值"作为 Objaverse 上的主指标，与整体 PSNR 并列报告；在 TexGaussian / Paint3D / TEXGen 的 hold-out 列表上做 per-mesh 评估，为与 baseline 对比打底。
  • 模型方向：以格点 IO 为基础，让 latent 数量随 mesh 复杂度变化（可变长度 / 层次化 latent），或改读出为按块解码；输入采样随面积自适应（大面切分或变长采样）。oracle 与 latent 数量扫描的结果决定优先级。
  • 数据方向：可选地剔除 const_frac > 0.95 的 1 万个调色板低模（它们对纹理学习几乎没有监督信号），或在损失中降低完全常数面的权重。
